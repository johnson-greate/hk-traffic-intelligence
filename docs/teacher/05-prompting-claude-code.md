# 第 5 課：怎樣向 Claude Code 下指示

[← 上一課：部署到 Cloudflare](04-deploy-cloudflare.md) · [課程目錄](README.md)

## 目標

- 學會幾種在本項目中有效的 prompt 寫法
- 認出 AI 回覆中的警號：沒有證據的聲稱、未核實的「完成」
- 建立一個習慣：每一個「完成」，都要求它拿出證據

## 核心概念

Claude Code 寫代碼很快，但它不知道你的限制、你的優先次序，也不一定會主動核實自己的成果。你的工作是**定方向、定界線、要證據**。

## 有效的 prompt

### 1. 先要計劃，批准後才動手

```text
讀 docs/ROADMAP.md，第一階段的兩項由你負責。
先給我一個計劃：會改哪些檔案、怎樣測試、分幾個 commit。
我批准之前不要改任何檔案。
```

PR #1 就是這樣開始的。開發期間亦發現「頂部數字是 8 個起點中的最小值」，於是先調整設計，才有過海決策卡（見[第 3 課](03-test-first.md)）。先看計劃，比事後看 diff 便宜得多。

### 2. 要求先寫測試

```text
排序邏輯放在 src/lib/harbour-choice.ts，做成純函數。
先寫 harbour-choice.test.ts，執行一次讓我看到它失敗，然後才寫實作。
```

### 3. 要求在瀏覽器核實

```text
用瀏覽器打開 http://127.0.0.1:4317，把地圖傾斜到最大，截圖給我看天空。
再把視窗調到 390 px 闊，打開決策卡，確認沒有被情報面板遮住，console 沒有錯誤。
```

PR #1 的手機版遮擋問題，正是這一步發現的。沒有這句，它很可能只會說「已加入卡片」。

### 4. 要求分開 commit

```text
天空和決策卡是兩件事，分兩個 commit。
Commit message 第一行講做了甚麼，內文講為甚麼。
```

結果見 [`d6d2dc2`](https://github.com/johnson-greate/hk-traffic-intelligence/commit/d6d2dc2) 和 [`b7f8b09`](https://github.com/johnson-greate/hk-traffic-intelligence/commit/b7f8b09)。

### 5. 講清楚環境限制

```text
這部 Mac 的內置硬碟只剩約 17 GB。
不要寫入 ~/ 或 /tmp，暫存檔放外置硬碟的 .cache/tmp。
不要 npm install 新套件，不要下載大檔案。
```

AI 不會自己知道你的硬碟快滿、公司網絡有限制、或者某些資料夾不能碰。不講，它就會用預設做法。

### 6. 講清楚甚麼不能做

```text
不要 push，不要開 PR，做完 commit 就停下，等我看過。
這是公開 repo，不要寫入帳號 ID、database ID、email 或 token。
```

### 7. 要求寫交接文件

```text
寫一份 handover：做了甚麼、目前狀態、未解決的問題、下一步。
只寫你親眼核實過的事，未核實的要標明。
```

本項目的 [`docs/handover/`](../handover/) 就是這樣產生的。下一個 session 由它接手，不用由頭解釋。

### 8. 收尾時要求重新檢查線上狀態

```text
不要相信上一份 handover 的狀態。
現在打開 /api/history?hours=48，數一數實際有幾行，與預期比較。
```

Cron 間歇被取消的問題（見[第 4 課](04-deploy-cloudflare.md)），就是在這樣的收尾檢查中發現的。

## 要警惕的訊號

| AI 這樣說 | 你應該追問 |
| --- | --- |
| 「已完成。」 | 你怎樣確認？給我看測試輸出、截圖或 curl 結果。 |
| 「應該可以運作。」 | 「應該」即是未試過。去試。 |
| 「測試全部通過。」 | 貼出指令和完整輸出。 |
| 「部署成功。」 | 線上網址回應甚麼？Cron 跑了幾次？寫了幾行？ |
| 「問題的原因是 X。」 | 有甚麼證據？可以重現嗎？若未證實，先加 log，不要改代碼。 |
| 「我順便改了 Y。」 | Y 不在要求之內，先解釋為何要改，否則撤回。 |
| 一大段總結，沒有指令輸出 | 要求原始輸出，不要總結。 |

本項目真實的例子：上線當晚的記錄是「已確認連續寫入兩行」。這句話是真的，但兩行證明不了 Cron 長期穩定。翌日數一數才知道 140 行只有 43 行。**證據要與聲稱的範圍相符。**

## 常見錯誤

**一開口就叫它「全部做完」。** 沒有計劃、沒有界線，結果往往是一個巨大的 commit，夾雜了你沒要求的改動。

**接受沒有證據的「完成」。** 每次都要求看到指令輸出、截圖或線上數據。

**未證實就修 bug。** 本項目遇到 Cron 被取消時，刻意不憑假設改代碼，先加診斷。AI 很樂意立即「修正」，你要叫停。

**沒有講限制。** 硬碟空間、公開 repo、不可 push，這些它都不會猜到。

**信 handover 多於信現狀。** 交接文件寫的是當時的狀態。動手之前先核實現在的狀態。

## 練習

1. 揀 [`docs/ROADMAP.md`](../ROADMAP.md) 中一項細的工作（例如「日夜光影」），寫一個 prompt，要求 Claude Code 先給計劃，不准改檔案。比較計劃與你預期的分別。
2. 在同一個 prompt 加入至少兩項限制（例如不可 push、不可安裝套件），觀察它有沒有遵守。
3. 它說完成時，用上表逐項追問，記錄它第一次回覆中有幾項聲稱沒有附證據。
4. 與同學交換 prompt，互相找出對方遺漏的限制或核實步驟。
